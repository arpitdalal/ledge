# Ledge

A personal cash flow tracker for understanding spending, income, and upcoming obligations.

Ledge is a production-minded starter app for AI coding-agent workshops. It is intentionally useful before the demo feature is added: participants can run it locally, inspect real domain boundaries, and extend a polished baseline without external services.

## Screenshots

Screenshots are generated by running the app locally.

- Dashboard: `http://localhost:3000/dashboard`
- Transactions: `http://localhost:3000/transactions`
- Reports: `http://localhost:3000/reports`

## Stack

- Next.js App Router
- TypeScript
- Tailwind CSS
- shadcn/ui-style local primitives
- Prisma
- SQLite
- Zod
- date-fns
- Recharts
- Vitest
- Playwright

No hosted database, auth provider, email service, queue, Redis, or third-party API is required.

## Setup

Prerequisite: Node.js 20+.

```bash
npm install
npm run setup
npm run dev
```

Then open `http://localhost:3000`.

The setup script copies `.env.example` to `.env` when needed, generates Prisma Client, applies the SQLite migration, and seeds demo data.

## Scripts

```bash
npm run dev          # start local dev server
npm run build        # production build
npm run start        # start production server
npm run lint         # eslint
npm run typecheck    # TypeScript check
npm run test         # unit + integration tests
npm run test:unit    # unit tests only
npm run test:e2e     # Playwright tests
npm run db:generate  # generate Prisma Client
npm run db:migrate   # create/apply local migrations
npm run db:seed      # seed demo workspace
npm run db:reset     # reset SQLite database and seed
npm run setup        # first-run local setup
```

- Shopping

Default income categories:

- Freelance

## Folder Structure

```text
app/                 Next.js routes and route-level loading/error states
components/ui/       shadcn/ui-style primitives owned by the app
components/layout/   app shell and navigation
components/*/        feature-focused React components
lib/db/              Prisma client and reusable demo seed
lib/domain/          business logic, data access, actions, calculations
lib/validation/      Zod schemas shared by forms and services
prisma/              schema, migration, seed entrypoint
scripts/             setup and test database helpers
tests/unit/          pure helper and calculation tests
tests/integration/   Prisma-backed service tests
tests/e2e/           Playwright browser flows
```

## Architecture Notes

The app uses a single local workspace instead of authentication. Domain logic stays out of route components:

- Transactions use URL search params for filtering and sorting.
- Server actions call service functions, then revalidate affected routes.
- Zod schemas are shared by client forms and service boundaries.
- Currency is stored as integer cents in SQLite to avoid floating-point drift.
- Reports use pure aggregation helpers that are unit-tested separately from Prisma access.
- Categories carry type, color, icon, and default/custom flags, which keeps future cash-flow views predictable.

Recurring transactions are intentionally not implemented. The schema and folders leave room for a future `RecurringRule` model and a future navigation section without forcing that concern into current transaction code.

## Testing

Run all non-browser tests:

```bash
npm run test
```

Run Playwright:

```bash
npm run test:e2e
```

Playwright starts a dev server against `prisma/e2e.db`, resets it, seeds it, then runs the browser tests.

## Why This Exists

This repo is the pre-demo app for an AI coding-agent workshop. It gives the agent a meaningful codebase with real constraints: local setup, domain boundaries, validation, charts, forms, tests, accessibility, and polished UI.

The later demo feature is:

**Recurring Transactions + Upcoming Cash Flow**

That feature should be added later by extending the existing domain and UI patterns, not by replacing them.
